# Documentation Governance

本文档定义 FileStation 项目的文档分层、更新规则和维护责任。

## 文档分层

### Layer 1: Agent 入口（最高优先级）

| 文档 | 用途 | 更新频率 |
|------|------|---------|
| `AGENTS.md` | Agent 第一入口，工作规则和安全规则 | 项目规则变更时 |
| `docs/CURRENT-STATE.md` | 当前实现状态，里程碑进度 | 每次功能变更后 |

### Layer 2: 设计参考

| 文档 | 用途 | 更新频率 |
|------|------|---------|
| `docs/superpowers/specs/2026-07-28-filestation-design.md` | 详细设计文档 | 重大架构变更时，版本号递增 |

### Layer 3: 架构决策

| 文档 | 用途 | 更新频率 |
|------|------|---------|
| `docs/adr/*.md` | 架构决策记录 | 重要技术决策时，不可修改 |

### Layer 4: 用户文档

| 文档 | 用途 | 更新频率 |
|------|------|---------|
| `README.md` | 项目介绍、快速开始 | 用户可见变更时 |

## 文档更新规则

### CURRENT-STATE.md

**必须更新的场景：**
- 完成一个功能模块
- 数据库 Schema 变更
- API 端点新增/修改/删除
- 开发里程碑进度变更
- 发现新的技术约束或风险

**更新内容：**
- 项目状态表格
- 当前阶段完成度
- 新增的技术约束
- 待办事项调整

### 设计文档

**版本控制：**
- 重大架构变更：版本号 +0.1（如 v2.2 → v2.3）
- 协议修正：版本号 +0.1
- 文字修正：不更改版本号

**变更记录：**
- 在文档头部记录版本历史
- 说明变更原因和影响范围

### ADR (Architecture Decision Records)

**格式：**
```markdown
# ADR-NNNN: 标题

## 状态
[proposed | accepted | deprecated | superseded]

## 上下文
决策背景和约束

## 决策
做出的决定

## 后果
正面和负面影响

## 替代方案
考虑过的其他方案及拒绝原因
```

**规则：**
- 一旦创建，不可修改内容
- 如需变更，创建新的 ADR 标记旧 ADR 为 superseded
- 编号递增，不允许跳号

## 文档冲突解决

当文档之间存在冲突时，按以下优先级处理：

1. `AGENTS.md` 的工作规则和安全规则
2. `docs/CURRENT-STATE.md` 的当前实现状态
3. 代码和测试的实际行为
4. `docs/superpowers/specs/` 的设计意图
5. `docs/adr/` 的历史决策背景

**冲突处理流程：**
1. 发现冲突时，以高优先级文档为准
2. 立即更新低优先级文档
3. 如无法确定，提交 issue 讨论

## 文档审查清单

每次提交前检查：

- [ ] `CURRENT-STATE.md` 是否反映当前实现？
- [ ] 新增 API 是否有对应文档？
- [ ] 数据库变更是否有迁移说明？
- [ ] 安全相关变更是否有风险提示？
- [ ] 文档中的代码示例是否可运行？

## 禁止事项

- **禁止** 在文档中记录真实密钥、密码、Token
- **禁止** 复制大段代码到文档（引用文件路径即可）
- **禁止** 在 `AGENTS.md` 中记录具体实现细节（保持抽象）
- **禁止** 修改已发布的 ADR 内容
